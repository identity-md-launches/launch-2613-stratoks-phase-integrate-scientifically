# Release review: integrated client

This is the contributor's separate source-and-evidence review, **not independent external approval**. The network verifier checks paths and bytes, not behavior. The exact release inventory is [release.json](release.json); the accepted backend/component inventory is verified unchanged by [preflight.json](preflight.json).

| Question | Review and evidence |
|---|---|
| Is the recovered application preserved? | The downloaded and retained ZIP match SHA-256 `8816bfda36545436f85d4ca0b13bd439be14fb3a6be285f25bd39f3edf8abd9e`. All recovered `web/` files were restored before editing. Manifests, lockfile, Vite/TS configuration, original renderer/icons/wallet, original tests and accepted backend files remain intact. The complete archive and earlier component remain available. |
| Does the inspector report real decisions? | `BrainBehavior.tsx` consumes the existing `GET /api/creatures/:id` field; it does not score actions or generate telemetry. Two separate browser contexts connected through real WebSockets, compared the same creature's full brain JSON to the server, and checked rendered scores/selected action/tick. The authoritative decision and digest are retained in each browser's `shared-decision.json`. |
| Is a reflex being sold as learned behavior? | Source labels map `model`, `rule`, `reflex` separately. Selection and reward plasticity are separate fields. The UI explains stochastic choice and in-flight actions across mode changes. Legacy mode is explicitly described as linear, with no KC activity invented. Candidate association values are raw readouts before the 2.5 gain; total scores include other game terms. |
| Does the lab use the implemented model? | `learningLab.ts` imports `World`, `scoreCandidate`, `selectCandidate`, `rewardAction` and the circuit parameters from the accepted server. It has no service/store/wallet/network import. Rewards and site identity are generated by seeded counterbalanced experiments; no expected preference is embedded in the UI. Ten-seed raw results and all failures/controls are retained. |
| Is causality distinguishable from scripted safety? | Equal innate scores, legacy and frozen controls, held-out evaluation, reward reversal and post-training output removal. Frozen and lesioned controls remain near chance. The experiments do not call emergency reflex selection. Cue conditioning counterbalances a fire marker's outcome; punishment-only location avoidance is reported separately. Synthetic successes do not establish animal validity or improved game survival. |
| Can demo controls touch production? | The lab runs in its own worker and has no transport. The browser test hashes the server world before/after all controls and downloads, checks equality, and records GET-only reads. The private world worker stops the old connection and is a separate world. The local launcher creates a temporary loopback service without reading production environment/configuration, and isolated settings override a saved remote server. No writable brain endpoint or operator activation UI was added. |
| Do authenticated memories and authorization survive? | `wallet.tsx`, `service.ts` and all server authentication code are unchanged. The recovered authenticated browser suite passed nonce/signature flows, actor-scoped uncertain retries, account switching, durable retry, history gaps/busy recovery and rate limits. No real wallet/key/payment was used; synthetic accounts are generated only by the retained tests. |
| Does persistence claim more than it tests? | Existing 68-test server suite includes deterministic restart, backup restore, preserved IDs/history/legacy weights and actual recovered-binary rollback on copies. The browser lab checks only its experiment checkpoint, including creature/brain/cues/RNG, and compares uninterrupted/restored choices. It does not call the Node-only full-world terrain serializer or claim browser disk persistence. The UI says tab-local state is discarded. |
| Is stale or incompatible data presented as current? | Unknown/missing interface version produces an unavailable state. HTTP failures retain data with a stale label; retries respect server backoff. WebSocket loss keeps the selected Brain view visible and labels it stale. A changed world ID, server source or restart epoch clears details before a new response. Actual mode is shown independently of the last decision. |
| Does the client silently activate the new mode on a real world? | No. Only the explicitly private browser world and disposable demo launcher use `mb-v1`. Production `DEFAULTS.world.brainMode` remains `legacy`; the operator's startup policy and persistence semantics are unchanged. |
| Are state, work and artifacts bounded? | Existing circuit/output/reward bounds remain unchanged. The lab retains 12 phases, has finite 200/300/400-trial commands, one worker, one watchdog, and terminates on panel close. JSON downloads revoke their object URL. All package installations/caches and browser libraries are outside the submission. The contribution budget counts complete added paths, not merely compressed files. |
| Are visual and release claims measured? | Production build, typecheck, unit/server regressions, actual two-context browser checks, screenshots, axe scans, pinned taste@1 and baseline/inventory checks are recorded. `dist/` uses relative assets and includes local fonts/notices. Browser runs pin the index digest and reject a build change during a run. No public URL, Docker/cgroup qualification or external approval is invented. |

Issues found and repaired in this integration: the original client lacked a brain-interface view; a first lab retention implementation used Node's `Buffer`; implicit select labeling did not expose the intended exact name; reconnection reset the selected view; and a saved remote URL could supersede the disposable launcher's configuration. The rendered fixes and source locations are in [VALIDATION.md](VALIDATION.md). A browser harness also needed to close the mobile panel before reaching the intentionally hidden pause control; that was a test correction, not a layout redesign.

Remaining release gates outside this client implementation: independent external review; exact target-host Docker/cgroup and long-duration capacity qualification; resolution of the recovered backend's standalone redistribution grant; owner-operated public HTTPS/WSS deployment; and IMD's public static URL assignment after submission. Scientific limitations remain those in [MODEL.md](../../docs/phase2a/MODEL.md), including engineered spatial/actions/wallet abstractions and weaker ecological outcomes in some prior tests. No restricted scientific dataset was added, and no production service was accessed.
